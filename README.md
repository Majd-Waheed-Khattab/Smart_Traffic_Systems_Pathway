# Smart Traffic Systems Pathway

## About

هذا المشروع نظام لاكتشاف وتصنيف المركبات في الفيديوهات المرورية باستخدام
YOLO11n. يستخدم النظام ByteTrack لتتبع المركبات وإعطاء كل مركبة رقم ID،
ويحفظ فيديوً جديدًا يحتوي على النتائج وإحصاءات بصيغة JSON. كما يقدّر سرعة
المركبات تقديرًا تقريبيًا ويميز المركبات التي تتجاوز حد السرعة.

الفئات التي يتعرف عليها النموذج هي:

1. `car`
2. `van`
3. `bus`
4. `truck`
5. `motorcycle`
6. `motorcycle_traffic_police`

## Repository structure

```text
src/
  inference_video.py       # تشغيل النموذج والتتبع وحفظ النتائج
  speed_logic.py           # منطق تقدير السرعة
  violation_config.py      # حد السرعة والألوان ومعايرة السرعة
models/
  best_continued.pt        # النموذج النهائي
classes.txt                # أسماء الفئات
requirements.txt           # مكتبات التشغيل

```

## Setup & Run

### المتطلبات

- Python 3
- اتصال بالإنترنت لتثبيت المكتبات
- Linux أو نظام يدعم Python وOpenCV
- النموذج الموجود في `models/best_continued.pt`
- فيديو إدخال، مثل `data/input/training_h264.mp4`

أنشئ بيئة افتراضية وثبّت المكتبات:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### تشغيل النموذج

ضع فيديو الإدخال في أي مسار مناسب، ثم شغّل:

```bash
python src/inference_video.py \
  --model models/best_continued.pt \
  --video data/input/training_h264.mp4 \
  --output-video outputs/inference/tracked_speed_video.mp4 \
  --output-stats outputs/inference/speed_statistics.json
```

ينشئ البرنامج المجلدات المطلوبة ويحفظ:

```text
outputs/inference/tracked_speed_video.mp4
outputs/inference/speed_statistics.json
```

لعرض الفيديو على Linux:

```bash
xdg-open outputs/inference/tracked_speed_video.mp4
```

لعرض الإحصاءات:

```bash
cat outputs/inference/speed_statistics.json
```

## Documentation

### طريقة التعامل مع المشكلة

عولجت المشكلة على مراحل: تجهيز صور المركبات وملفات labels، توحيد أسماء
الفئات، تدريب نموذج YOLO11n للكشف والتصنيف، ثم إضافة ByteTrack للتتبع بين
الإطارات. بعد ذلك أضيفت معالجة الفيديو وحفظ الإحصاءات وتقدير السرعة.

### البيانات المستخدمة ومصدرها

تم دمج مجموعات بيانات مرورية متاحة للمشروع في مجموعة موحدة. أُزيلت
التكرارات، ووُحّدت أسماء الفئات، وقُسمت البيانات إلى مجموعات تدريب وتحقق
واختبار. أسماء الفئات النهائية موجودة في `classes.txt`.

بيانات التدريب الأصلية غير مرفقة داخل المستودع بسبب حجمها. يجب وضعها محليًا
إذا أراد المستخدم إعادة التدريب؛ أما تشغيل النموذج النهائي فلا يحتاج إلى
مجموعة التدريب.

تم جمع data لكل البيانات المطلوبة وتم تنزيلها من موقع roboflow اما ميتورات الشرطة فتم تنزيل كب صورة على حدى لمحدودية ايجادها ضمن مواقع تم تنزيلها من google و ايضا من youtube 

تم توسيم صور `motorcycle_traffic_police` من موقع https://www.makesense.ai/

### التدريب وData Augmentation

بدأ النموذج من أوزان YOLO11n، ثم تمت مواصلة التدريب على البيانات الموحدة.
استُخدمت عمليات augmentation المتاحة في Ultralytics، ومنها تغيير الحجم،
التحويلات اللونية، التكبير والتصغير، الإزاحة، القلب الأفقي، وMosaic.
النموذج النهائي المرفق هو نتيجة مواصلة التدريب، ويحفظ في:

```text
models/best_continued.pt
```

### النتائج

قورِن النموذج قبل مواصلة التدريب مع النموذج النهائي على نفس مجموعة الاختبار.
كانت النتائج:

| المقياس | قبل مواصلة التدريب | النموذج النهائي |
|---|---:|---:|
| Precision | 0.402 | 0.769 |
| Recall | 0.351 | 0.690 |
| mAP50 | 0.291 | 0.757 |
| mAP50-95 | 0.174 | 0.502 |

تشير النتائج إلى تحسن النموذج النهائي في الكشف والتصنيف. يجب ملاحظة أن
السرعة المقدرة تقريبية وليست قياسًا مروريًا رسميًا.

- جمع البيانات من مصادر متعددة، ثم دمجها وتوحيد ملفات `data.yaml` لتتوافق
  مع بنية المشروع.
- اختلاف أسماء الفئات وتصنيفاتها بين مصادر البيانات، مما تطلب توحيدها قبل
  بدء التدريب.
- وجود صور متقاربة مأخوذة من مقاطع فيديو، ولذلك كان من الضروري تقسيم
  البيانات بطريقة منظمة لتقليل تكرار الصور وتسربها بين مجموعات التدريب
  والاختبار.
- بطء عملية التدريب بسبب استخدام وحدة المعالجة المركزية (CPU).
- انقطاع التيار الكهربائي أثناء التدريب، مما تطلب استكمال التدريب من آخر
  نقطة حفظ باستخدام ملف checkpoint.
- صعوبة تقدير سرعة المركبات بدقة بسبب عدم توفر معايرة حقيقية للكاميرا
  والمسافات داخل المشهد.
- عدم توفر عدد كافٍ من الصور الجاهزة لفئة
  `motorcycle_traffic_police`، مما استدعى البحث اليدوي عن صور مناسبة من
  مصادر مثل YouTube وGoogle، ثم تجهيزها لتناسب متطلبات التدريب.
خل المشهد.
- عدم وجود dataset للتدريب بصيغة yollo11n فقمنا استيدالها ب yolo8v لانهم متقاريب جدا فيما بينهم .
- توسيم بعض الصور يدويا
### نقاط الضعف

- السرعة المقدرة تعتمد على معامل معايرة ثابت، ولذلك قد لا تمثل السرعة
  الحقيقية.
- قد يتغير ID المركبة إذا فقدها المتتبع لعدة إطارات.
- تعتمد دقة الكشف على الإضاءة وزاوية الكاميرا وجودة الفيديو.
- عدد مرات الكشف عبر الإطارات لا يساوي عدد المركبات الفريدة.
- ضعف في التعرف على `motorcycle_traffic_police` بسبب محدودية ال dataset المدخلة للتدريب

## ملاحظات التشغيل

إعدادات السرعة الحالية موجودة في `src/violation_config.py`. السرعة القصوى
المستخدمة لتمييز المخالفات هي 50 كم/ساعة، ومعامل التحويل الحالي هو 8 بكسل
لكل متر، وهما قيمتان تقريبيتان يجب معايرتهما حسب الكاميرا والموقع.
